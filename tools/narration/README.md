## Punctuation pauses (October 30, 2026)

Project Settings → Narration includes Punctuation pauses, default on, stored as the boolean punctuationPauses in the existing project/collaborator preferences. Two plain labels are translated in all seven locales. Applies only to new/regenerated recordings: old exact-source audio remains reusable until Recreate/Regenerate is requested. No manuscript text, punctuation, canonical data, or model weights are rewritten.

The new narration-punctuation.js owner processes each generated mono PCM chunk before early playback and WAV assembly. Minimum boundary gaps: commas 120ms, semicolon/colon 180ms, sentence endings 300ms, ellipses 350ms (one gap, not one per dot). It tops up the existing aligned inter-word gap, or trailing aligned/acoustic silence, rather than adding the full pause blindly. Common English/Spanish abbreviations, initials/acronyms, decimal/thousands separators, closing quotes and Spanish opening punctuation are handled conservatively. Missing or overlapping/unusable alignment is a safe no-op, not a guessed cut through speech. It is a pacing aid, not a language parser or intonation fix. At a synthesis-chunk boundary, the existing trailing gap is measured; the next not-yet-generated chunk's leading silence is not predicted.

Post-processing shifts subsequent word times by the inserted sample count and preserves UTF-16 start/end positions and word durations. Cumulative chunk offsets use adjusted durations. The exact same processed PCM goes to early playback, the complete saved WAV, and therefore WAV exports; no second inference or extra model download is required. The browser engine API adds a sixth optional boolean argument: generate(text, voice, onprogress, onchunk, pace=1, punctuationPauses=false). Main UI explicitly passes its default-on preference, held fixed per run and GPU→CPU retry. Standalone diagnostics retain false unless requested.

Cache POST/returned metadata adds strict boolean punctuation_pauses (missing defaults false for existing clients; strings/numbers/null rejected). When true, the server appends -punctuation-v1 after any -pace-<value> suffix to its derived backend/language-specific engine identity before computing the existing recording hash. False preserves old identities. Regeneration publishes the replacement before retiring its selected original; failed generation/upload leaves the original intact. Recordings remain regenerable, excluded from backups, and local-only.

## Settings-only pace, pitch, and audio download (October 29)

Project Settings → Narration adds generationPace (0.85/0.9/0.95/1/1.05/1.1/1.15, default 1) and pitch (-4 through +4 integer semitones, default 0) to the existing collaborator/project UI preferences. Neither adds controls to the main panel. Generation pace is sent to both HeadTTS setup and synthesis. It affects new/regenerated audio only; existing exact-source recordings remain reusable until explicit regeneration. POST metadata accepts generation_pace, validated against the same finite allowlist (booleans/strings rejected). Missing/default 1 preserves original engine identity and hash; other values append -pace-<value> to the backend/language-specific engine string before hashing. Returned metadata includes generation_pace. Keep the per-run value fixed across all passages and GPU→CPU retries. Source offsets and word timestamps come from that generation, not guessed rescaling.

Playback pitch uses a same-origin AudioWorklet (narration-pitch-worklet.js), two crossfaded variable-delay lines, through narration-playback.js for native saved WAV and early AudioBuffers. No third-party DSP dependency, model download, canonical mutation, or new network origin. Zero pitch is a direct bypass; nonzero changes pitch without changing the playback clock, duration, or source word timings (small algorithmic delay, at most about 66ms). Modest adjustments recommended; this is an audio effect, not emotion/formant control or a guarantee of naturalness at extremes. Native playback retains browser pitch preservation when speed changes; pitched streaming compensates its rate-induced pitch in the worklet. Worklet preparation failures surface rather than silently claiming the requested pitch. Hosted must serve this same-origin script under its reviewed worklet/script CSP and test its browser/AudioContext matrix.

Download audio is a nested prompt inside Narration settings: Selection / Chapter / Entire book. Chapter is the captured focused chapter, ignoring Continue chapters; Book is the entire active manuscript document, not other tabs/projects. Capture selection before entering the prompt. Export uses only current saved recordings, preferred voice when available, with no generation or audio autoplay. Every nonempty prose passage and explicit chapter title must have current covering audio; missing/stale/incomplete coverage blocks the download with localized guidance, never silently emits an incomplete book. Exact saved selections export directly; subranges of larger recordings trim at recorded whole-word timing boundaries. Selections cutting through a spoken word are rejected. Partial word generation can instead produce an exact separately saved selection.

narration-export.js fetches each recording through the existing authorized adapter, parses RIFF chunks, retains mono PCM16 at 24kHz as Blob slices, and writes one lossless audio/wav file in manuscript order. No re-encoding, duplicate alternate voices, MP3 dependency, full-book float decode, server archive, or automatic backup inclusion. Export keeps the original generated pace; playback speed/pitch are deliberately not baked in (prompt explicitly says so). WAV is broadly editable/playable and lossless but large (~173MB/hour); RIFF is capped below 4GiB and larger work must be exported by chapter. Browser Blob/download resource limits can still be lower. Project/document switches abort publication; generation/delete conflict guards apply. Deleted audio remains inaccessible; user-initiated exported downloads are ordinary files outside the regenerable project cache.

Explicit recreation replaces the selected recording, including when source text or voice changes its cache ID. Publish the new WAV and metadata before retiring the original; failed synthesis/upload must preserve the original. Other partial selections are not automatically removed.
- Generation shows a slim **estimated** progress bar immediately, updating every 150ms between actual chunk callbacks. It advances monotonically, eases between checkpoints, and never reaches 100% until successful completion. Loading, synthesis and cache saving are separate phases. If a phase exceeds its estimate, show Taking longer than estimated rather than a misleading zero-second countdown. Failure/project switching clears the timer without pretending success. All status labels are translated in seven languages.
- Opening Narration prepares the existing local model/worker in the background (no manuscript synthesis or external request). The ready worker is reused across generations/panel toggles until page reload. Model initialization still has a real cost; prewarming moves it ahead of the Generate click rather than claiming to eliminate it.
- `narration-progress.js` keeps up to eight numeric timing samples per language/cold-or-warm synthesis category and a median startup history in browser localStorage, separated by CPU-thread count and GPU backend. It stores only durations, character counts and chunk counts—not prose, project IDs, recording IDs or telemetry. Chunk counts account for per-inference overhead (English sentence boundaries, bounded Spanish phonetic chunks). First-run fallbacks are estimates seeded from the local benchmark; subsequent runs learn the browser's timings. Corrupt/denied storage falls back safely. This calibration is not project data or backed up/synced.

Existing browser-fetched audio cannot be remotely revoked. Cloud must supply an equivalent project-authorized delete/restore adapter, not rely on filesystem operations.

Original source and selected text remain unchanged; normalization is one UTF-16 unit per apostrophe, preserving word offsets. Already cached audio needs Recreate to pick up this correction.

- Small gutter play triangles appear only while Narration is open. Closing pauses playback and removes gutter icons and both highlights. No annotations are inserted inside saved prose.
- View independently toggles a light passage highlight and stronger spoken-word highlight. Ranges use the browser CSS Highlight API. Timings come from the timestamped Kokoro model, not character-count estimates. Unmatched returned words are skipped rather than assigned invented source positions.

Voice lists default to the interface language; there is no automatic manuscript language detection or translation. Four default English choices: US Heart (af_heart, female), US Michael (am_michael, male), UK Emma (bf_emma, female), UK George (bm_george, male). Old recordings remain playable, and no recordings are deleted by the roster change.
- English retains HeadTTS's en-us phonemizer, including the UK voice embeddings Emma and George; do not claim a separate British phonemizer. Spanish uses the bundled MIT `@piper-plus/g2p/es` 0.4.2 rule-based phonemizer (Latin American seseo/yeísmo), not English rules, eSpeak, or Piper's speech model. Its IPA is passed through HeadTTS's supported `phonetic` input with original word subtitles. Map Piper PUA trill U+E01D to Kokoro `r`, and affricate U+E054 to `ʧ`; never send PUA tokens to the model. ## Owner's explicit storage decision

**Store recordings inside the project; do not back them up. They can be generated again.**

Local cache: `<project-root>/narrations/<64-hex-record-id>.json` and matching `.wav`. These are regenerable derivatives, outside project SQLite, revision history, canonical image assets, and checkpoint assets. No schema migration or canonical manuscript mutation.

Normal `.breadmaker` exports and Recovery backups use frozen canonical snapshots, which do not include this folder. Whole-installation `/api/data/export` now explicitly excludes `narrations` paths. Test coverage checks both Recovery ZIP and whole-data ZIP exclusion. Import/restore does not require cache presence; restored projects regenerate narration. This policy concerns Breadmaker backups, not OS-level backups such as Time Machine.

Do not move recordings into `/api/assets` without new ownership work: image validation/GC, snapshots and backup enumeration treat those as canonical assets.

## Boundaries and interfaces

Editor files:

- `static/js/features/manuscript/narration.js`: UI, selection snapshots, chapter queues, Audio playback, source validation, transient gutter markers, highlights. `narrationStore` is the storage adapter; `narration.engine` is the inference adapter.
- `static/js/features/manuscript/narration-playback.js`: saved-WAV facade and transient AudioBuffer streaming, pause/resume, buffering, seek/restart and speed. Only complete audio is stored.
- `static/js/features/manuscript/narration-engine.js`: `BreadmakerKokoroEngine.generate(text, voice, onprogress, onchunk, pace=1) -> {blob: WAV Blob, timings: [{start,end,time,duration}], metrics}`. `onchunk` receives `{buffer,context,timings,duration}` with cumulative timings/duration; `{reset:true}` discards a failed GPU preview before CPU retry. Callback receives `{loading:true}`, then `{completed,total}` synthesis chunk counts. Word positions are UTF-16 offsets **within the selected text**, times/durations are seconds. Full passage start/end are UTF-16 offsets within `source_text`.
- `static/js/features/manuscript/narration-progress.js`: numeric device calibration and smooth estimated progress. Engine callbacks now also include `phase:'loading'|'synthesis'`; UI adds `saving`. Generation additionally returns source-free `metrics:{inferenceMs,chars,cold,threads,backend}` for diagnostics; it does not upload these to the cache API.
- `src/api/manuscript/narration.py`: local-only cache routes. All return 404 outside runtime.mode=local. Existing request middleware binds project context and editing leases. No hosted filesystem fallback.
- `tools/narration`: isolated pinned JS dependency/build/install tooling, lockfile, real inference smoke. Core Editor startup remains build-step-free and does not load any model until generation is requested.
- `tools/narration/spanish.mjs`: Spanish phonetic-input/source-subtitle adapter. Installer bundles only its Spanish G2P and number modules into `static/vendor/narration/spanish.mjs`; the rest of Piper is not shipped or run. Loaded lazily only when a Spanish voice is generated.

Local HTTP contract:

1. `GET /api/narrations` -> `{records:[record...]}`.
2. `POST /api/narrations`: multipart `metadata` JSON + `file` WAV. Metadata: `block_id`, `source_text`, selected `text`, `start`, `end`, `voice`, `timings`. Server validates block existence in bound project, current source ignoring whitespace, exact UTF-16 selected range, known voice, timestamps and WAV format. Stale text returns 409.
3. `GET /api/narrations/{id}/audio` -> audio/wav, private/no-store.
4. `DELETE /api/narrations/{id}` -> `{undo_token}`. Active metadata is renamed to `.deleted-<random-64-hex-token>-<id>.json` inside the same excluded cache folder. Listing ignores hidden metadata; audio requires active metadata. Tokens are project scoped.
5. `POST /api/narrations/{id}/restore`, JSON `{undo_token}` -> restored record. Unknown/consumed token returns 404; a newly generated recording with the same ID prevents overwriting on Undo (409).

For explicit recreation, POST metadata additionally includes `replaces:<selected-record-id>`. Server checks it belongs to the same bound-project block before publication. If the new ID differs, it removes the selected old entry only after new publication; an unchanged ID is atomically overwritten. No automatic deletion of preexisting duplicates or separate selections.

Returned record: `{id,block_id,source_text,text,start,end,voice,language,timings,duration,engine}`. Server derives `language` from the validated voice (`en-us`, `es`, `fr`, `it`, `ja`, `pt-BR`, `zh-CN`); if supplied in metadata it must agree. Existing English records without `language` remain playable. Metadata additionally accepts validated `backend:'wasm'|'webgpu'` (default wasm for backward compatibility). Server derives engine identity: CPU retains `kokoro-timestamped-q8-v1` or `kokoro-timestamped-q8-es-piper-0.4.2-v1`; GPU uses corresponding `fp32` identities. New languages append `-<language>-frontend-v1` as detailed above. Existing q8 recordings remain reusable; Recreate atomically replaces the selected entry if the backend changes. `id=sha256(UTF8(JSON compact([block_id,source_text,start,end,voice,engine])))`. Cloud must preserve the different engine identity and derive/validate the voice-language pair server-side. No project ID in the hash because the directory/object namespace is project scoped. Current local bounds: 20,000 selected characters, 100,000 source characters, 10,000 timing entries, 400,000 metadata characters, 32MiB audio per recording; mono PCM16 WAV at 24kHz. Individual audio then metadata writes use atomic replacement (metadata published last). On failure, no canonical text changes.

```
node install.mjs
```

This explicitly downloads the model once. `node install.mjs --runtime-only` rebuilds runtime files without redownloading the model. Install the optional Python language requirements above for Japanese, Mandarin and Italian. Merely changing the UI/source without installing dependencies and assets is not a working installation.

Model, voices, dictionaries, JS and WASM are served same-origin. `transformers-local.mjs` sets allowRemoteModels=false and localModelPath explicitly; WASM uses `min(4,max(1,floor(hardwareConcurrency/2)))` CPU threads only when crossOriginIsolated, otherwise one. This cap leaves CPU headroom for writing. No manuscript is sent to a provider. HeadTTS runs inference in a module Worker. The adapter prefers WebGPU/fp32 only when the optional local model and a browser GPU adapter are available; otherwise WASM/q8. Both use the same pinned timestamped model revision, voice files and the same validated generation pace (default 1). GPU initialization failure terminates its worker/closes its AudioContext and falls back to CPU. GPU setup/inference error or 90s inactivity resets partial preview and retries once on CPU. Headless Chromium has no GPU adapter here and tests CPU fallback; the chat browser does support GPU.

Installer reproducibly patches pinned HeadTTS initialization deadlines: connect/ready 90s/90s GPU, 60s/30s CPU, preserving worker-init error details. Outer timeout is 120s GPU / 90s CPU. These are failure bounds, not enforced waits. Installer fails if upstream patch anchors change; do not edit ignored vendor output manually.

Local responses now set COOP=same-origin and COEP=require-corp to enable shared-memory WASM workers. Hosted/hosted_dev headers remain unchanged; without isolation, the runtime safely selects one thread. Do not blindly apply local COOP to hosted: review popup authentication, cross-origin integrations and browser compatibility first. This is separate from paid entitlement/storage. Existing CSP remains same-origin and its local-only wasm-unsafe-eval allowance; no unsafe-eval or external model/text transmission was added.
