# Hosted / Local Persistence Seams — Milestone 1

**Baseline:** Editor 10.3.41 → Milestone-1 candidate 10.3.43; local Schema 42 remains unchanged.

## Why this document exists

Breadmaker local persistence is intentionally SQLite + filesystem. The hosted rewrite is intentionally **not** going to make Firestore/GCS pretend to be SQLite or a local directory tree. Milestone 1 therefore does two things before the hosted data model is frozen:

1. extracts the cross-cutting runtime contracts that can already be environment-neutral; and
2. freezes every remaining direct local-engine dependency so later milestones can remove them deliberately instead of adding more cloud conditionals.

The machine-readable source of truth is `docs/HOSTED_LOCAL_DEPENDENCY_INVENTORY.json`, generated by `scripts/generate_hosted_local_dependency_inventory.py`.

## New environment-neutral runtime ports

- `ProjectRepository` — project catalog, membership, ownership/selection, trash/restore. **No filesystem `Path` requirement.**
- `AssetStore` — logical content-addressed assets via bytes + logical API paths. **No filesystem `Path` requirement.**
- `ProjectUsageService` — project/account byte and count projections for hosted quotas without walking directories in request code.
- `IdentityProvider.avatar_bytes()` — profile avatar reads no longer require a local path at the HTTP boundary.

## Explicit native bridges

These are deliberately separate and optional in `RuntimeServices`:

- `NativeProjectStore`
- `NativeAssetStore`
- `NativeHistoryStore`
- `NativeBackupStore`

Local and the old undeployed VM-hosted composition provide them. The future Cloud Run composition must leave them `None`. Any caller that uses `runtime.native_*` / `runtime.native.require_native_*()` is explicit migration debt, not an accidental cloud contract.

## Cross-cutting ownership moved behind ports in Milestone 1

- project rename now synchronizes the local workspace registry + SQLite project title inside `LocalProjectRepository`; the HTTP route no longer opens SQLite;
- hosted quota accounting now uses `runtime.usage` rather than directly walking workspace paths in request code;
- project assets are served as bytes through `runtime.assets` rather than `FileResponse` over a resolved local path;
- image upload publishes through the logical asset port;
- DOCX/PDF/BreadReview/Cuts asset packaging reads logical asset bytes rather than assuming a durable project asset path;
- profile avatar HTTP reads use `avatar_bytes()` rather than exposing an avatar path;
- package/history/backup operations that truly remain filesystem-shaped are now accessed through explicit native bridges.

## Important sequencing decision

Milestone 1 does **not** invent fake Firestore-shaped CRUD interfaces for manuscript/review/canvas/map/task state before we have frozen the hosted data model. Those feature modules currently contain substantial SQL transaction/invariant logic. The remaining direct engine callers are frozen below and become the input to Milestone 2 (hosted data model) and Milestones 3–5 (Firestore/GCS adapters + hosted route migration).

Adding a new direct dependency on `storage.database`, `storage.mutations`, `storage.context`, `storage.invariants`, `storage.undo`, `revision_store`, etc. from an API/backend owner is a regression. The allowlist may shrink only.

Pure helpers such as `storage.values`, `workspace.filesystem.safe_name`, and `workspace.models.WorkspaceError` are not persistence authority and are tracked separately.

## Exit condition for Milestone 1

- local runtime still defaults with zero hosted/GCP dependency;
- local Schema 42 is unchanged;
- environment-neutral ports contain no required filesystem path for project catalog/assets/usage;
- native filesystem dependencies are explicit and discoverable;
- the dependency inventory is enforced by tests and cannot grow silently;
- user runs the full Editor + Cloud verifier; the model does **not** run it.

After the user reports green, Milestone 2 may freeze the actual hosted Firestore/GCS entity mapping. At that point feature-domain repository interfaces can be defined from the product model rather than from SQLite table shape.
